<interfaces>
기존: api/accounts.py:list_accounts는 accounts의 id, alias, status, base_currency만 반환한다. 이를 GET /api/v1/accounts로 재사용하며 새 계정 목록 API를 만들지 않는다. get_single_active_kb_connection_for_account, BrokerSyncCoordinator._kb_lease, read_retained_daily_prices, DailyPriceRequest/DailyPriceBarRead가 실제 기존 심볼이다.
신규: GET /api/v1/accounts/{account_id}/market-data/snapshot?market=US|KR&amp;exchange=NAS|NYS|AMX|KOSPI|KOSDAQ&amp;symbol=... . account_id는 기존 UUID 형식, US ticker는 trim/uppercase 후 [A-Z][A-Z0-9.-]{0,15}, KR은 ASCII [0-9]{6}. 시장별 exchange 조합을 거부하며 extra/duplicate query keys도 거부한다. 사용자 입력 limit/date/TR/path는 받지 않는다.
신규 JSON DTO MarketSnapshot: account_id, market, query_market, symbol, currency(USD|KRW), source(kb), acquired_at(UTC ISO), provider_as_of(null 또는 근거 있는 offset timestamp), provider_timezone(null 또는 공식 계약이 명시한 timezone), delay(status=delayed|realtime|unknown, minutes=integer|null), quote(last/bid/ask=decimal-string|null), bars(date=YYYY-MM-DD, open/high/low/close=decimal-string, volume=decimal-string|null). 현 계약에서는 realtime을 생성하지 않는다. 날짜는 거래일 문자열을 그대로 보존하며 provider time/timezone을 추정하지 않는다. listing exchange 필드는 추정해서 만들지 않는다. snapshot identity는 account_id/market/query_market/symbol 모두를 묶는다.
bars는 최대 250개, 날짜 오름차순·중복 없음·실제 calendar date. 가격은 finite nonnegative Decimal, OHLC는 strictly positive 및 low ≤ open/close ≤ high; volume은 있으면 finite nonnegative. 과도한 행 수·invalid date/number·echo 불일치는 전체 실패. 빈 candles와 없는 quote는 명시적인 no_data이며 조작한 0으로 성공시키지 않는다. quote 일부가 없고 실제 candles가 있으면 nullable fields를 유지한다.
오류는 고정 code/message의 닫힌 집합: invalid_request(422), account_unavailable(404), connection_unavailable(503), provider_contract_unverified(503), unsupported_instrument(422), provider_rejected(502), provider_invalid_response(502), no_data(404), provider_timeout(504). 브라우저 전송 실패는 backend_offline로 별도 표시한다. 알 수 없는 provider 거절을 unsupported로 단정하지 않는다. raw exception/provider message는 응답·로그·console에 붙이지 않는다.
