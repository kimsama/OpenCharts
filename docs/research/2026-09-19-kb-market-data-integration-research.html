1. 실행 결론

현재 코드 확인 공식 공개 샘플 제안 미검증

결론: 현재 KB 백엔드의 계좌·매매일지 종목 기반 차트 API를 그대로 OpenCharts의 범용 시장 데이터 공급자로 쓰기에는 범위가 좁다. 미국 계좌 종목의 일봉과 분봉 조회는 재사용할 수 있지만, 임의 종목 검색, 국내 주식, Cboe BZX 같은 거래소 식별, 최신 호가의 지연 상태가 계약에 없다.

권고안은 KB 백엔드에 주문과 분리된 전용 읽기 API를 두고 OpenCharts에 얇은 어댑터를 추가하는 것이다. 이 문서는 그 설계 방향을 제안할 뿐, 구현·브로커 호출·설정 변경을 승인하거나 수행하지 않았다.

재사용: 미국 KB 인증 수명주기, 일봉 캐시, V2 분봉과 파생 봉, 계정 격리. 신규 계약: 임의 심볼, 미국·한국 통합 식별, quote, 지연·관측 시각. 미검증: 진짜 실시간, Cboe용 시장 코드, 국내 장중 파라미터와 호출 한도.

2. 범위와 종목 식별

공식 공개 정보 Roundhill의 DRAM은 Memory ETF이고 Cboe의 상장 상품 목록은 거래소를 Cboe BZX로 확인한다. MU는 Micron Technology 보통주이며 Nasdaq 공식 종목 페이지에서 Nasdaq 상장을 확인할 수 있다. 두 티커는 의미와 거래소가 다르므로 대체할 수 없다.

  • DRAM: Roundhill ETF, Cboe BZX, USD. Nasdaq로 추정하거나 MU로 대체하지 않고 KB provider code를 별도 검증한다.
  • MU: Micron Technology 보통주, Nasdaq, USD. DRAM과 독립된 종목 키다.
  • 005930: 국내 예시. KRX 내 실제 시장과 KRW를 보존하고 코드는 선행 0을 포함한 문자열로 처리한다.

정정된 해석: 현재 KB 차트 라우팅이 NAS·NYS·AMX만 받는다는 사실만으로 DRAM 조회가 불가능하다고 단정할 수는 없다. 다만 Cboe BZX를 어떤 KB 요청 코드로 보내고 응답에서 어떻게 확인하는지는 아직 검증되지 않았다. 따라서 Nasdaq로 임의 매핑하는 것도 허용할 수 없다.

4. 현재 흐름과 제안 흐름

현재 OpenCharts 실행 경로

현재 코드 확인 src/services/api.ts:26은 API를 demoApi에 고정하고, src/services/ws.ts:28의 DemoWsClient는 네트워크 소켓이 아니라 로컬 타이머 피드를 시작한다. 이 client의 connected는 로컬 feed 상태이며 broker 연결 증거가 아니다. 번들 종목은 BTCUSD, ETHUSD, SOLUSD, BNBUSD, XRPUSD, ADAUSD 여섯 crypto다. market-data.ts HTTP wrapper는 정의되어 있지만 현재 실행 경로에서는 사용되지 않는다.

제안 연결 모드는 demo API와 로컬 demo feed를 우회해 읽기 전용 KB 어댑터를 선택한다. demo 모드는 별도로 유지할 수 있다. 연결 모드에서는 paper engine을 분리하고 quick-order를 포함한 주문 action을 비활성화한다. 과거 candle REST와 quote snapshot/poll을 구분하고 KB polling을 WebSocket처럼 가장하지 않는다.

5. 현재 KB 백엔드 계약

외부에서 사용할 수 있는 조회

경로입력출력 핵심제약
GET /api/v1/accounts 없음 불투명 계정 ID, 별칭, 상태, 기준 통화 시장 종목 검색이 아니다.
GET /api/v1/accounts/{account}/journal 기간, symbol, review state, limit trade_subject_id, normalized_market, normalized_symbol 이미 수집된 계정 종목만 나온다.
GET .../chart-series 계정 + 매매주제 미국 일봉 OHLCV, 체결 표식, source, freshness, coverage 범용 티커 요청이 아니다.
GET .../chart-series-v2 interval, regular session, cache_only, from/to, max_bars, cursor 일봉·주봉·분봉 union, instrument, timezone, provenance, freshness, cursor 현재 scope 해석이 미국만 허용한다.

캐시와 신선도

  • 현재 코드 확인 일봉 성공 캐시는 최대 24시간 동안 fresh이며, 실패 시 기존 캐시는 stale과 제한된 실패 사유로 반환할 수 있다.
  • 현재 코드 확인 현재일 분봉 스냅샷의 fetched-fresh 창은 60초다. 특정 과거 거래일을 요청한 스냅샷은 하루 동안 재사용한다.
  • 현재 코드 확인 분봉은 프로세스 메모리에 최대 32개 account/subject 스냅샷만 보관한다. 영구 시세 이력이 아니다.
  • 현재 코드 확인 cache_only=true는 공급자 호출을 막는다. 캐시가 없으면 값을 합성하지 않고 실패한다.
  • 미검증 fresh는 “방금 가져왔다”는 뜻이지 “거래소 실시간”이라는 뜻이 아니다. 현 계약은 공급자 지연 종류를 응답하지 않는다.

시장·인증 경계

  • 현재 차트 scope는 미국만 통과시키고 provider market은 NAS, NYS, AMX로 제한한다. KRX 런타임 차트 경로는 없다.
  • 브라우저가 계좌번호·앱 키·토큰을 받지 않는다. 백엔드가 로컬 credential binding과 활성 connection을 소유한다.
  • 웹 앱은 loopback host와 same-origin mutation 증거를 검사한다. 기존 로컬 조회 API에는 bearer 인증 요구가 없으며, 보호 경계는 local host 검증과 변경 요청의 exact-origin header 검사다.
  • 다른 origin의 브라우저에서 직접 읽도록 단순 CORS 개방하지 않는다. OpenCharts 웹 앱과 함께 제공되는 same-origin 제한 read proxy 또는 동일 origin serving을 사용한다.

현재 문서와 코드의 차이: 오래된 설명에는 V2 분봉 7개가 비활성이라고 적힌 부분이 있으나, 조사한 현재 코드에는 미국 1분 봉 공급자 호출과 파생 interval 경로가 연결되어 있다. 이 보고서는 실행 코드 쪽을 현재 사실로 기록하고, 실제 계좌 호출 성공 여부는 별도 미검증으로 남긴다.

6. KB증권 공식 공개 샘플 후보

공식 공개 샘플 공개 문서의 ZIP(73,160바이트)에서 필요한 필드만 요약했다. 실제 계좌 성공, 권한, 호출 한도, 장중 지연, 운영 안정성의 증거는 아니다.

샘플후보 용도공개 필드·예시해석 한계
GSA10020미국 현재 시세 후보output.dataBody.mrkt_prc_clsf = 15분지연실시간으로 표시하면 안 된다.
GSC10060미국 차트output.dataBody.mrkt_prc_clsf = 15분지연현재 코드의 fetch freshness와 시장 지연을 분리해야 한다.
GSS10030미국 quote 후보now_prc_p4, b_askprc_p4, s_askprc_p4이 샘플만으로 지연 수준을 확정할 수 없다.
IVM10050국내 종목 정보 후보종목 식별 관련 공개 예시검색 범위·시장 코드 의미를 검증해야 한다.
IVU10070국내 현재가·호가 후보now_prc, b1_aprc, s1_aprc; 샘플 입력 ovtm_mkt_clsf=1샘플 입력을 장중 운영 기본값으로 주장하지 않는다.
IVS11560국내 차트 후보chrt_clsf=D, minute_tck_indx=일, is_cd=005930일봉 예시일 뿐 분봉·페이지·정정 계약은 미검증이다.

지연 표시 원칙: OpenCharts UI는 최소한 공급자 분류, 공급자 기준 시각, 애플리케이션 관측 시각, 캐시 나이를 구분해야 한다. 공개 샘플에 “15분지연”이 있는 미국 데이터는 실제 계약 확인 전까지 그보다 강한 표현을 사용하지 않는다. REST를 자주 polling해도 원천 데이터의 지연이 실시간으로 바뀌지 않는다.

7. 대안과 트레이드오프

A
기존 계정·매매주제 차트 API를 그대로 사용

가장 빠른 미국 과거 차트 시범안이다. 이미 거래한 종목만 가능하고 KRX, 임의 종목 검색, quote, Cboe 정체성, 지연 표시가 해결되지 않는다. 전체 목표에는 불충분하다.

B
전용 KB 읽기 API + OpenCharts 어댑터 권고

계좌 저널과 시장 데이터 조회를 분리한다. 동일한 서버 소유 인증과 캐시를 재사용하면서 미국·KRX instrument, candles, quote의 명시적 계약을 만든다. 범위가 가장 선명하고 향후 provider 교체도 격리된다.

C
처음부터 진짜 스트림 구현

지연이 가장 낮을 수 있지만 공식 WebSocket 계약, entitlement, replay, 재연결, REST overlap이 검증되지 않았다. 공식 계약이 확인되기 전에는 도입하지 않는다. polling snapshot을 WebSocket event처럼 위장하지 않는다.

8. 제안하는 식별·인증·데이터 구조

제안 아래는 구현 승인이 아닌 최소 계약 초안이다.

정규화된 종목 키

instrument = { region: "US" | "KR", venue: "CBOE_BZX" | "NASDAQ" | "NYSE" | "KRX_KOSPI" | ..., providerVenueCode: string, symbol: string, // "DRAM", "MU", "005930"; 선행 0 보존 currency: "USD" | "KRW", exchangeTimezone: string }

Quote 응답 원칙

quote = { instrument, last: decimal | null, bid: decimal | null, ask: decimal | null, provider: "kb", providerAsOf: instant | null, observedAt: instant, // provider 응답 획득 시각, HTTP 전달 시각 아님 cacheAgeMs: number, delay: { kind: "realtime" | "delayed" | "unknown", minutes: number | null }, session: "regular" | "pre" | "after" | "closed" | "unknown" }

bid/ask가 없으면 null로 둔다. OHLC의 close, high, low로 bid/ask를 합성하지 않는다.

Candle 응답 원칙

candles = { instrument, interval: string, exchangeTimezone: string, bars: [{ openedAt, tradingDate, open, high, low, close, volume: decimal | null }], providerAsOf: instant | null, observedAt: instant, // provider 응답 획득 시각 cacheAgeMs: number, delay, freshness: "fresh" | "stale", coverage: { from, to }, nextCursor: string | null }

observedAt은 provider 응답 획득 시각이며 HTTP 전달 시각이 아니다. 캐시 재사용 시 각 client가 데이터 나이를 알 수 있도록 cacheAgeMs를 함께 계산한다. USD/KRW를 유지하고 UTC instant와 현지 거래일을 함께 보존한다. 누락 volume은 null이며 0으로 바꾸지 않는다.

인증과 권한

  • KB app key, secret, access token, 원본 계좌번호는 OpenCharts 응답, 브라우저 저장소, 로그, 저장소 파일에 포함하지 않는다. 백엔드만 고정된 공식 KB 호출에 사용하며, 기존 API가 제공하는 불투명 account scope ID는 사용할 수 있다.
  • OpenCharts에는 종목·시세·출처·지연 정보만 전달한다.
  • 허용 기능은 symbol info, candles, quote snapshot의 읽기 전용 allowlist로 고정한다.
  • 주문 생성·전송·정정·취소와 일반 목적 provider passthrough는 포함하지 않는다.
  • KB 연결 모드는 crypto demo feed를 우회하고 paper engine과 분리한다. quick-order 등 주문 action은 숨김뿐 아니라 실행 경로에서도 비활성화한다.
  • quote에 실제 bid/ask가 없으면 null로 두며 candle OHLC에서 합성하지 않는다.
  • OpenCharts와 KB 백엔드 사이는 same-origin 제한 read proxy로 연결한다. 새로운 bearer/token 체계를 추가하거나 기존 same-origin 보호를 조용히 해제하지 않는다.

9. 작게 나눈 구현·검증 단계

상태: 아래 단계는 제안이며 승인되지 않았고 구현되지 않았다. 이 조사에서 앱 코드, 설정, 브로커 연결, 네트워크 수집은 변경하지 않았다.

  1. 공식 계약 고정: 미국 GSS10030/GSC10060과 국내 IVM10050/IVU10070/IVS11560의 요청 필드, 시장 코드, 지연, 장 구분, 호출 제한, 오류를 날짜가 있는 계약표로 기록한다.
  2. 종목 식별 POC: DRAM의 Cboe BZX provider code, MU의 Nasdaq code, 국내 005930의 시장·통화를 사용자 소유 권한 아래 제한된 읽기 1회로 확인한다.
  3. sanitized fixture: 비밀정보·계좌정보가 없는 미국/국내 quote·candle fixture를 만들고 누락 volume, 휴장일, 지연 필드를 확인한다.
  4. KB 전용 읽기 API: instrument lookup, candles, quote snapshot만 추가한다. 주문 surface와 기존 저널 정본은 건드리지 않는다.
  5. OpenCharts 어댑터: 기존 candle API와 market-data store 앞에서 새 응답을 변환하되 quote snapshot과 WebSocket tick을 구분한다.
  6. 운영 검증: USD/KRW, 선행 0, 거래소 시간대, 캐시·지연 표시, stale 전환, 공급자 오류, 재시작 뒤 분봉 캐시 소실을 확인한다.
  7. 스트림 결정: 공식 WebSocket 계약과 replay/overlap 증거가 갖춰진 경우에만 별도 단계로 판단한다.

검증 성공 기준

  • 미국과 국내 각각에서 올바른 symbol·venue·USD/KRW·거래소 날짜로 candle과 quote fixture 및 제한된 실제 읽기가 일치한다.
  • DRAM/MU 및 KRX 세부 시장의 잘못된 market mapping은 조용히 대체되지 않고 명시적으로 거절된다.
  • 지연을 확정할 수 없으면 unknown으로 응답·표시하며 fetched-fresh를 realtime으로 표현하지 않는다.
  • KB 백엔드 offline 시 demo 값이나 마지막 OHLC를 quote로 대체하지 않고 bounded unavailable/stale 상태가 표시된다.
  • 빠른 symbol 전환 중 이전 요청의 늦은 응답이 새 symbol의 chart·quote를 덮어쓰지 않는다.
